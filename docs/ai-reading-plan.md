# AI 个性化解读与继续提问计划

最后更新：2026-07-31

## 1. 目标

在现有固定牌义和组合摘要之上增加可选的 AI 能力：

1. 用户可以继续使用推荐问题，也可以填写自定义问题。
2. 完成抽牌后，先立即看到现有固定解读。
3. 用户主动点击“AI 深度解读”后，生成与本次问题、牌阵和牌位相关的个性化解读。
4. 用户可以围绕同一次牌局继续提问，首版最多 3 次。
5. AI 超时、限流、服务不可用或输出校验失败时，固定解读仍可正常阅读、保存和分享。

AI 是增强层，不参与抽牌随机过程，也不替代结构化牌义库。

## 2. 首版范围

### 纳入

- 推荐问题与自定义问题作为 AI 上下文。
- 单牌、时间流、凯尔特十字；接口本身兼容其他配置化牌阵。
- 一次结构化深度解读。
- 同一牌局最多 3 次自由追问。
- 首次调用前的数据发送说明与明确确认。
- 加载、超时、重试、限流和固定解读降级。
- AI 内容标识、边界提醒和会话删除。
- Web 与微信小程序共享请求模型和展示模型。

### 暂不纳入

- AI 决定抽到什么牌或修改正逆位。
- 无限对话、跨牌局长期记忆和用户画像。
- 账号、云同步、付费额度和会员。
- AI 读取历史记录、联系人、设备信息或未主动提交的内容。
- 语音、图片识别、真人咨询和自动心理评估。

## 3. 用户流程

```text
选择推荐问题或填写自定义问题
  → 选择牌阵并完成抽牌
  → 立即展示固定解读
  → 用户主动点击“AI 深度解读”
  → 首次调用显示数据发送说明
  → 服务端生成结构化解读
  → 展示整体观察、逐牌联系、行动建议和反思问题
  → 用户可继续提问，首版最多 3 次
  → 结束、删除会话或继续使用固定结果
```

结果页不得等待 AI 才显示内容。保存牌局与分享固定结果不依赖 AI 服务。

## 4. 分层架构

```text
Web / 微信小程序
  ├─ 固定 InterpretationView（现有）
  ├─ AiReadingService 接口
  └─ AI 解读与追问 UI
             │ HTTPS
             ▼
服务端 / 云函数
  ├─ 请求校验、限流与会话边界
  ├─ Prompt 组装与内容安全
  ├─ 模型供应商适配器
  └─ 结构化响应校验与降级
             │
             ▼
模型 API
```

客户端不得包含模型密钥、供应商私有参数或可绕过的系统提示词。模型供应商通过服务端适配器隔离，切换模型时不修改牌局领域逻辑。

## 5. 请求上下文

只发送生成当前解读必需的数据：

```ts
type AiReadingRequest = {
  requestId: string;
  question: string;
  categoryId: string;
  spread: {
    id: string;
    name: string;
  };
  cards: Array<{
    cardId: string;
    orientation: "upright" | "reversed";
    positionId: string;
    positionName: string;
    meaning: {
      summary: string;
      keywords: string[];
      topicText: string;
      positionText: string;
      advice: string;
    };
  }>;
  locale: "zh-CN";
  clientVersion: string;
};
```

不发送本地历史、CloudBase 文件地址、牌面图片、联系人、定位、设备相册或与本次牌局无关的数据。问题和追问均设置长度上限，牌义只发送审核过的紧凑字段。

## 6. API 草案

### 创建解读

`POST /api/ai/readings`

成功响应：

```ts
type AiReadingResponse = {
  sessionId: string;
  reading: {
    overview: string;
    cardInsights: Array<{
      cardId: string;
      positionId: string;
      insight: string;
    }>;
    connections: string;
    actions: string[];
    reflection: string;
    boundary: string;
  };
  limits: {
    remainingFollowUps: number;
  };
  expiresAt: string;
};
```

### 继续提问

`POST /api/ai/readings/{sessionId}/messages`

请求包含 `requestId` 和本次问题；响应返回回答、剩余追问次数和会话过期时间。服务端只携带原始牌局、首次解读及最近必要消息，不无限累积上下文。

### 删除会话

`DELETE /api/ai/readings/{sessionId}`

首版会话使用短期有效期。是否持久化以及保留多久必须在选定部署平台后写入正式隐私说明；在此之前不得默认长期保存。

## 7. 输出与提示词边界

模型必须：

- 基于传入牌义、问题和牌位进行关联，不编造未抽到的牌。
- 使用“可能、可以观察、值得留意”等非确定性表达。
- 将内容定位为娱乐与自我探索，不声称预测事实结果。
- 不推断第三方真实思想、忠诚度、疾病、死亡、怀孕、违法结果或投资收益。
- 对医疗、心理危机、法律、财务等高风险问题明确边界并建议寻求适当专业帮助。
- 输出符合固定 Schema；客户端不直接渲染模型生成的 HTML 或 Markdown。

所有回答显示“AI 生成内容”标识。输入校验、系统提示、输出 Schema 校验和必要的内容审核均在服务端完成。

## 8. 成本与稳定性

首版默认策略：

- 固定解读免费且始终可用，AI 由用户主动触发。
- 每个牌局最多生成 1 次深度解读、继续提问 3 次。
- 对问题、追问、牌数、上下文和输出长度设置硬限制。
- 请求使用幂等 `requestId`，避免重复点击造成重复计费。
- 客户端显示明确加载状态并阻止同一请求并发提交。
- 服务端配置单次超时、每日设备或会话额度、IP 级限流和供应商熔断。
- 超时、限流、无效输出和供应商故障统一回退到固定解读，不影响牌局记录。
- 记录请求状态、耗时、错误类型和估算用量，不记录完整问题正文到普通业务日志。

具体模型、单次输入输出上限、每日额度和预算，需要在供应商选定后通过压测确定。

## 9. 隐私与平台要求

首次启用 AI 前应明确告知：

> 为生成个性化解读，本次问题、抽到的牌、正逆位和牌阵位置将发送至 AI 服务。不会发送本地历史记录或牌面图片。

用户拒绝后继续显示固定解读，不重复强制弹窗。隐私说明必须列出处理目的、数据项、服务提供方、保存期限、删除方式和跨境情况；微信小程序还需同步隐私保护指引、合法请求域名和审核材料。

## 10. 实施阶段

### AI-0：决策与服务验证

- 确认模型供应商、部署位置、可用地区、预算和隐私条款。
- 用脱敏样例验证结构化输出、中文质量、延迟和单次成本。
- 确认 Web 与小程序可共同访问的 HTTPS 服务地址。

退出条件：供应商和预算已记录，密钥只存在服务端，样例请求可稳定返回 Schema。

### AI-1：共享契约与服务端

- 在共享包增加请求、响应、错误码和 Schema。
- 建立 provider-neutral 服务端适配器。
- 实现创建解读、继续提问、删除会话。
- 增加校验、限流、幂等、超时、内容边界和固定解读降级。
- 增加单元测试与服务契约测试。

退出条件：无客户端密钥；正常、超时、重复请求、越界输入和无效输出均有测试。

### AI-2：Web 接入

- 结果页增加“AI 深度解读”入口、首次同意、状态展示和重试。
- 增加结构化 AI 解读区与最多 3 次继续提问。
- 增加删除会话、退出后恢复策略和本地数据边界。
- 先在 Web 灰度验证生成质量、延迟和成本。

退出条件：固定结果不受影响，AI 全链路通过移动端浏览器验收。

### AI-3：微信小程序接入

- 复用共享契约和 UI 状态，接入小程序网络适配。
- 配置合法域名、隐私保护指引、失败提示和真机调试。
- 复核“星简集”展示文案与平台审核材料。

退出条件：真机完成首次解读、3 次追问、删除、超时和无网络降级验证。

### AI-4：灰度与评估

- 观察 AI 入口点击率、成功率、P95 延迟、平均追问次数和单牌局成本。
- 抽样检查输出边界和用户反馈，不把完整问题写入分析事件。
- 根据数据决定是否调整额度、模型或开放更多牌阵。

## 11. 验收清单

- 自定义问题能进入 AI 上下文，推荐问题行为不变。
- AI 不影响抽牌结果、固定解读、历史、分享和离线主流程。
- 单次解读严格对应本次牌局和全部牌位。
- 每个会话最多 3 次追问，刷新、重复点击和并发不会绕过限制。
- 服务不可用时显示可理解的提示并保留固定解读。
- 客户端构建产物不包含模型密钥。
- 输入输出边界、幂等、超时、限流和结构化校验均有自动测试。
- 用户可查看数据发送说明并删除 AI 会话。
- Web 和微信小程序分别完成隐私与平台配置核验。

## 12. 开发前待确认

1. 模型供应商与具体模型。
2. 服务端部署位置及 Web / 微信共用域名。
3. 可接受的月度预算和单用户每日额度。
4. AI 会话仅短期保存，还是允许用户主动保存。

这些选择不会改变共享牌义、牌阵、抽牌或固定解读结构。
